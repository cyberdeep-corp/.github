Welcome to CyberDeep Corporate Support.

We aim to make our projects accessible, understandable, and easier to use. Whether you are experiencing a technical issue, need help configuring a project, or have questions about our software, this document explains how to find assistance.

This policy applies to publicly available projects maintained under the official CyberDeep Corporate GitHub organisation.

---

## 1. Before Requesting Support

Before submitting a support request, we recommend:

1. Read the repository's `README.md`.
2. Review the installation and configuration documentation.
3. Check existing GitHub Issues.
4. Review recent releases and known limitations.
5. Ensure you are using a supported version.
6. Check whether the issue is specific to your environment.

Providing sufficient information helps us understand and investigate your issue more effectively.

## 2. Support Channels

Choose the appropriate channel based on the nature of your request.

| Request Type | Recommended Channel |
|---|---|
| General questions | GitHub Discussions, where enabled |
| Technical problems | GitHub Issues |
| Bug reports | GitHub Issues |
| Feature suggestions | GitHub Discussions or Issues |
| Documentation problems | GitHub Issues |
| Security vulnerabilities | Private vulnerability reporting |
| Contribution assistance | Pull requests and Discussions |

Not every repository necessarily supports all of these channels.

### GitHub Organisation

[CyberDeep Corporate on GitHub](https://github.com/cyberdeep-corp)

Browse our repositories to find the project relevant to your request.

## 3. Technical Support

For technical assistance, please provide:

- Project or repository name.
- Software version or commit.
- Operating system and environment.
- Installation and configuration details.
- Steps to reproduce the issue.
- Expected behaviour.
- Actual behaviour.
- Relevant error messages or logs.

Please remove credentials, access tokens, personal information, and other confidential data before sharing diagnostic information.

We may request additional information if necessary.

## 4. Bug Reports

If you encounter unexpected behaviour, submit a detailed bug report through the relevant repository's GitHub Issues section.

A useful report should contain:

**Title:** A short description of the problem.

**Environment:** Relevant operating system, browser, runtime, and project version.

**Steps to Reproduce:** A clear sequence of actions that produces the issue.

**Expected Result:** What should happen.

**Actual Result:** What happens instead.

**Evidence:** Relevant logs, screenshots, or error messages.

Before submitting, check whether another issue already describes the same problem.

## 5. Feature Requests

We welcome suggestions that improve the functionality, usability, reliability, and maintainability of our projects.

When suggesting a feature, explain:

- The problem you are trying to solve.
- The proposed functionality.
- Why the feature would be useful.
- Potential implementation considerations.
- Any relevant examples or references.

Feature requests are evaluated according to project objectives, technical feasibility, security implications, and available development resources.

Submission does not guarantee implementation.

## 6. Security Support

Security-related concerns require special handling.

**Never publish sensitive vulnerability details in public GitHub Issues or Discussions.**

If you discover a potential vulnerability:

1. Review our `SECURITY.md`.
2. Use GitHub Private Vulnerability Reporting where available.
3. Provide a responsible, minimal description of the issue.
4. Avoid sharing real credentials or private user information.
5. Allow the maintainers an opportunity to investigate.

Security reports should be submitted through authorised private channels.

Read our [Security Policy](./SECURITY.md).

## 7. Installation & Configuration Assistance

For installation and configuration problems, please consult the relevant repository documentation first.

Common areas include:

- Required dependencies and runtime versions.
- Environment variables.
- Database configuration.
- API credentials and integrations.
- Deployment configuration.
- Network and connectivity requirements.
- Build and dependency errors.

Never share production secrets or private configuration files in public support requests.

## 8. Response Expectations

CyberDeep Corporate aims to review support requests as resources permit.

Please understand that:

- Support is provided on a best-effort basis.
- Response times are not guaranteed.
- Some projects may have limited maintenance activity.
- Complex issues may require additional investigation.
- Feature requests may not be accepted.
- Unmaintained or archived projects may have limited or no support.

We encourage users to provide clear, reproducible information to help improve the support process.

## 9. Community Assistance

We encourage constructive collaboration between users and contributors.

When helping other users:

- Be respectful and professional.
- Provide accurate and relevant information.
- Avoid sharing unverified solutions as established facts.
- Do not request passwords, private keys, or confidential information.
- Respect the project's Code of Conduct.

Read our [Code of Conduct](./CODE_OF_CONDUCT.md).

## 10. Third-Party Services

Our projects may integrate with external services, APIs, hosting providers, libraries, and other infrastructure.

Issues originating from third-party providers may require assistance from those providers.

CyberDeep Corporate cannot guarantee the availability, performance, or behaviour of external services outside our control.

## 11. Contributions and Community Participation

If you would like to help improve a project rather than simply request assistance, you are welcome to contribute.

Useful contributions include:

- Bug fixes.
- Documentation improvements.
- Testing and quality assurance.
- Performance improvements.
- Accessibility improvements.
- Defensive security enhancements.
- New features aligned with project objectives.

Read our [Contributing Guidelines](./CONTRIBUTING.md).

## 12. Professional & Organisational Enquiries

For enquiries concerning:

- Software collaboration.
- Open-source partnerships.
- Technical discussions.
- Project coordination.
- Organisational matters.

Please use an official communication channel published by CyberDeep Corporate.

Always verify that a communication channel genuinely belongs to the organisation before sharing sensitive information.
